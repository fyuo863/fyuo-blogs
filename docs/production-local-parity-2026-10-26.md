# 线上与本地差异核对：2026-10-26

本轮修复基于 `84b0ec5`（线上 v0.6.8），最终发布 v0.6.11。以现有本地组件和操作为基准，复用登录框、管理面板、内容编辑器，没有另做一套设计。v0.6.9 被 Linux 滚动范围测试拦截，v0.6.10 在部署前主动取消并补入插件外链修复，未将这些中间版本替换到生产。

## 1. 本轮发现并修复的差异

| 范围 | v0.6.8 的线上行为 | 最终行为与验证 |
| --- | --- | --- |
| 登录入口 | 公共站跳到 www，独立管理应用固定渲染首页背景，原路由和页面实例丢失 | 在当前页面上打开弹窗；原 URL、查询参数、锚点、搜索输入、滚动位置和插件实例保留 |
| www 的普通页面 | 所有路径进入独立管理应用，首页、博客、插件路由和本地不同 | `/`、`/blog`、`/plugins` 使用与本地相同的 AppLayout / StudioFrame；只有 `/manage` 是隔离管理文档 |
| 登录和管理视觉 | 页面背景由另一套入口决定 | 直接复用 SignInModal / AdminPanel 和 studio.css，隔离文档背景透明；390、768、1440、1920px 下，同数据、同字体、静止动画条件的组件位置及像素对比通过 |
| 弹窗关闭与键盘 | 页面导航导致原状态丢失 | 关闭后恢复焦点；背景 inert；管理文档内处理 Tab 和 Escape；刷新普通页面不自动打开后台 |
| 插件发布后的主站目录 | 独立窗口内的 `fyuo:plugins-changed` 无法到达主页面 | 通过校验来源和窗口引用的消息通知主站，发布、排序和下线后刷新目录，原阅读页面继续挂载 |
| www 浏览插件 | 管理域禁止执行上传插件，原先没有与本地一致的浏览入口 | www 保留公共外壳，插件在公共域 iframe 执行；完整页面使用 `__plugin_embed`，不会误用 `__plugin_preview` 的降帧模式；查询参数和锚点保留 |
| 插件外链 | 新隔离容器默认阻止弹出新标签页 | 允许公共插件主动打开外链，验证新标签页打开且原插件路由不变；历史 iframe 插件自身的 sandbox 保持不变 |
| 字幕插件权限 | Nginx 显式禁止麦克风 | 公共域允许麦克风/屏幕采集能力，www 向公共插件 iframe 委托；仍需用户主动触发并通过浏览器权限询问，加载页面不会自动采集 |

管理 iframe 仅通知是否登录、角色、开关状态和目录刷新；不向公共主页面传递用户名、token 或 API Key。来源、父窗口和 iframe 引用均校验。

## 2. 保留的环境差异及其影响

| 差异 | 本地 | 生产 | 对操作的影响 |
| --- | --- | --- | --- |
| 登录凭据 | 回环地址的可信开发环境使用 localStorage | 仅 www 管理文档使用 sessionStorage，公共插件始终 `user=null` | 登录与管理仍是当前页面弹窗；登录不会给上传插件授予账号权限。关闭标签页后可能需要重新登录 |
| 历史插件内编辑 | 可信本地 module 测试可以直接收到 user/token，旧 desk 编辑链接仍可使用 | 上传插件不接收 token，写操作由管理面板的 CONTENT 完成 | **历史插件内直接编辑及 `?desk=...` 开编辑器，不与本地可信测试入口等价。** 统一内容面板的文章、图片上传、首页内容和旅行记录可用；本轮没有恢复向插件传凭据 |
| 数据与插件 | Playwright 使用明确的示例文章、插件和用户；`preview:studio` 是只读演示 | 读取真实数据库与已发布插件版本 | 不复制示例文章，不上传、发布、重排或删除插件。线上当时仅发布 AI Coding 1.1.0；其他插件是否出现取决于管理员发布状态 |
| 网络策略 | Vite 开发服务代理 API，未设置生产 CSP | HTTPS、Nginx 反代、登录限流、跨域 API 禁止、插件来源隔离 | 相同的界面组件不意味着开发服务器与生产安全策略相同；已按真实 CSP 和 Permissions-Policy 做双域浏览器回归 |
| 外部服务 | 本地可能已缓存字体、README、云图和语音模型 | 各浏览器的网络与缓存独立 | 外部资源可用性、字体首次加载、模型下载时间可能不同；不承诺网络时延与动画帧率逐帧相同 |

账号和数据库数据未复制。没有用伪造凭据执行生产管理写入，也没有改动生产文章、地点、Key 或插件发布状态。

## 3. 首页数据来源

本地和线上构建均读取 `frontend/src/showcase/showcase.config.json`：`fyuo863/fb-basement` / `main` / `showcase.json`，每 60 秒刷新。现场读取的专辑为：fyuo-blogs、fyuobot-ts、go-file-fetch、GeeMem，共 4 张。

它不是“枚举 GitHub 账号的所有仓库”。README 只为已配置专辑补充封面。配置仓库启用后，加载中、读取失败或明确空列表都不能回退到旧数据库项目列表；这一点已有回归测试。

另一个现存行为需要区分：管理面板“首页内容”编辑的是后端 `/api/v1/home-content`，**不会提交或修改 GitHub 的 showcase.json**。所以在启用配置仓库的首页中，修改旧数据库项目不会增删展示专辑；需要修改展示仓库。这是当前本地、线上共有的内容边界，不是部署遗漏。
