# 网站安全检查 · 2026-10-01

## 结论

存在基础认证和网络隔离，但不足以称为完善防御。已公开且已经收到自动化扫描。优先补齐 MCP 会话认证、请求限速/大小限制、管理面隔离，再完善浏览器防护与恢复能力。扫描痕迹不等于入侵成功；此次检查不能证明服务器从未被入侵。

范围：本地工作区源码、线上 v0.5.0 主服务、线上 Nginx 配置、监听端口、UFW、SSH 生效设置、Docker 隔离、最近 24 小时最多 10000 行 Nginx 日志、少量普通 HTTPS 请求。只读审计，没有压测、密码猜测、利用线上会话或修改生产配置。现有未提交改动完整保留。

## 已验证的防护

- HTTPS 可正常访问；配置仅允许 TLS 1.2/1.3，存在证书自动续期定时器。
- 未认证的管理插件列表、MCP 请求返回 401。注意：MCP 后续会话认证仍有下述缺陷。
- PostgreSQL 和 Redis 仅绑定宿主机 127.0.0.1，Go 后端与 MCP 没有独立发布宿主机端口。
- 密码使用 bcrypt；认证 token 使用 HMAC-SHA256、恒定时间签名比较及过期时间。
- 线上 AUTH_TOKEN_SECRET 已设置、长度至少 32，独立于 DB_PASSWORD，未匹配所检查的几个开发占位值；这不等于证明随机性。管理员自动初始化关闭，token 有效期 24 小时。未尝试猜测真实管理员密码。
- SSH 密码登录关闭，公钥登录开启；UFW 已启用。
- 插件上传仅管理员可用，存在 ZIP 大小、解压大小、条目数、路径、符号链接及重复版本检查。模块插件是信任代码，不是沙箱。
- AI Coding 同步接口使用独立上传密钥、字段白名单、大小限制和持久化卷；公开接口只返回用量汇总。

## 优先发现

### 高：MCP 会话没有绑定已验证的请求身份

位置：mcp/blog-publisher/src/http.ts:20、28、89。已读取线上 /app/dist/http.js 确认相同逻辑。

只检查请求携带非空 API key，未在创建会话前验证密钥。已有 transport 按 sessionId 查询，不比较当前密钥与会话创建者，工具客户端沿用创建时的密钥。若有效 sessionId 泄漏，存在跨身份调用/关闭会话风险；没有 sessionId 时不意味着直接获得他人权限。UUID 降低猜中概率，但不能代替身份绑定。会话 Map 未见数量上限或空闲到期机制，也有资源耗尽风险。

修复：每次请求验证 key，sessionId 绑定身份或密钥指纹；不匹配返回 403；会话到期和数量限制；key 撤销后不能沿用已有会话。不要仅凭无 key 返回 401 判断 MCP 已安全。

### 高：没有应用登录限速，默认请求体无限制

位置：nginx.conf:4、30；backend/internal/handler/user.go:26；backend/internal/service/auth.go:28。

线上 Nginx 未发现 limit_req / limit_conn。登录没有账户失败次数、退避或二次认证。client_max_body_size 0 表示没有上限；虽然插件上传在 Go 层限流量大小，Nginx 仍可能先缓冲大请求。图片上传只检查扩展名，没有硬大小上限和真实图像格式校验。后端 HTTP 超时限制有帮助，但不能替代 Nginx 请求体限制。未做大请求或高频实测。

修复：登录按 IP 与账户双维度限速；通用 JSON 设小上限，插件 ZIP 单独约 33 MiB，图片单独上限和 MIME/解码校验；API 及 MCP 设置合理并发与频率限制，避免破坏正常长连接。

### 高优先级加固：同机管理面和额外服务暴露较宽

宝塔面板 TCP 16123 监听 0.0.0.0，UFW 对任意来源放行；SSH TCP 22 也对任意来源放行。UFW 还放行 20、21、888、8888、39000–40000 和 8443；并非所有端口都有服务监听。同机还运行代理相关服务。SSH passwordauthentication=no，但 permitrootlogin=yes，fail2ban 未运行。

监听及 UFW 放行不等于已证明互联网可达：阿里云安全组未核验，未进行公网端口扫描。建议管理面经 VPN 或限定管理 IP；核对并关闭不使用的放行规则，保留正常代理功能。不要直接批量关端口以免锁死管理通道。

### 中高：浏览器凭据与同源模块插件共享信任域

位置：frontend/src/services/authStorage.js:20。管理员 token 存储 localStorage；module 插件运行在同源环境，可读取 localStorage、发起有权限请求。插件资源 JS 的 CSP 响应头不会成为宿主 HTML 文档的 CSP，也不能把已加载的 module 变成沙箱。未发现可直接利用的内容 XSS，不应把架构风险表述为已确认 XSS。

建议只安装审查过的插件；管理中心与公开插件隔离到不同 origin，并重新设计凭据与 CSRF 防护。单纯隐藏登录入口或把 token 改成 HttpOnly，不能完全阻止同源恶意脚本以管理员身份发请求。

### 中：页面缺少安全响应头与敏感路径拒绝规则

首页实测缺少 HSTS、CSP/frame-ancestors、X-Content-Type-Options、Referrer-Policy。/.env 与 /.git/config 返回 HTTP 200，但内容逐字等于首页，不是密钥或 Git 文件泄漏，是 SPA fallback。建议明确拒绝点文件（保留 ACME challenge），避免所有未知路径落到成功页。

添加合适的安全头；CSP 先 Report-Only 验证，必须兼容现有插件动态 import、侧栏同源 iframe、内联样式及外部地球贴图。HSTS includeSubDomains/preload 不应在未核对其他子域前启用。

### 中：依赖存在安全公告，容器资源与权限隔离不足

一次成功的 frontend npm audit --omit=dev 返回 4 个受影响依赖节点（3 high、1 moderate、0 critical），包含 Axios、React Router。公告包含 Node HTTP adapter、SSR/RSC 等适用条件，不能直接等同于当前静态 React 页面可被利用。后续 npm 审计请求及 MCP 依赖审计因 registry TLS 网络错误未完成；Go/镜像 CVE 扫描未执行。

线上 backend 与 MCP 以 root 运行、可写根文件系统、没有显式内存限制；privileged=false。建议依赖升级并运行旧插件兼容回归，给关键容器设置非 root、最小能力、合理内存/PID/日志上限。需同时检查历史插件内打包的依赖，更新宿主不等于更新所有旧插件依赖。

### 中：恢复与告警尚未得到验证

保留两个 tag 镜像仅能回退程序，不能恢复数据库、插件文件、上传内容和独立统计卷。检查到的 admin/root cron 与系统 timer 中未见本站业务备份；宝塔备份、云快照和外部备份未核验，因此结论是“未验证”，不是“肯定没有”。

建议定时异地备份 PostgreSQL、插件卷、上传卷和统计卷，执行一次恢复演练；监控磁盘、服务异常、401/429 激增及备份失败。未核验云 WAF/CDN/DDoS 防护，Nginx 限速本身无法抵御饱和链路的大流量攻击。

## 扫描证据

最近 24 小时、最多 10000 行的 Nginx 日志抽样得到 4378 行：.env 路径匹配 107 行、.git 匹配 85 行、WordPress 匹配 36 行、PHP 匹配 156 行。类别可重叠，不是独立攻击次数，也不能用响应 200 推断扫描成功。

## 建议实施顺序

1. 修复 MCP 会话身份绑定和有效密钥校验，加入过期与数量上限。
2. 为登录、API、上传配置限速、并发与请求体大小上限。
3. 收紧服务器管理入口，核验阿里云安全组；做好备份和恢复验证。
4. 安全头、token 撤销/会话管理、依赖更新和容器最小权限。
5. 若网站流量或被攻击情况增加，再选择适合备案/地域的 CDN、WAF 和 DDoS 防护。

以上是本次证据范围内的优先项，不是完整渗透测试或无漏洞保证。此次没有更改线上防护配置。
