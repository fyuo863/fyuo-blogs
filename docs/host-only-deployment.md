# 主站与插件独立部署

## 当前规则

- 部署流水线只构建主站及其后端服务，不构建、打包、安装或发布 index/journal/travel。
- 后端镜像不包含 `builtin-plugins`；启动只连接数据库和插件存储，不写入默认插件。
- 前端发布目录仅包含宿主 JS/CSS 与 favicon，不复制插件公共图片和地球贴图。
- 全新数据库没有页面插件，首页显示空站引导，管理员仍能登录管理中心上传 ZIP。
- `/` 使用已发布列表中排序第一的插件；不要求存在名为 index 的插件。旧 `/blog`、`/travel` 地址保留为兼容入口，但不自动安装对应页面。
- 已有安装升级时保留所有插件及其发布状态、版本、排序和文件。升级不会清空旧的自动安装插件；如果不再需要，由管理员手动下线。

## 管理员首次配置

1. 部署主站，使用已配置的管理员账号登录。
2. 进入 fyuo-control. → plugins.，选择 ZIP，点击“上传草稿”。
3. 选择版本，点击“发布版本”；仅上传或保存顺序不会发布。
4. 上移/下移并保存顺序，第一项已发布插件作为首页。

插件构建是独立操作：`npm --prefix frontend run build:plugins -- index`，ZIP 位于 `frontend/plugin-packages`。该命令不再复制到后端内置目录。仓库中的 `backend/builtin-plugins` 仅保留为历史兼容测试样本，不进入 Docker 构建上下文。

## 升级不改变插件

插件文件存储在命名卷 `backend_plugins`（容器内 `/app/plugin-storage`），清单、版本、发布状态和顺序存储在 PostgreSQL 的 `postgres_data` 卷。本地使用已有的本地数据库卷。主站镜像、前端静态目录和这些卷相互独立。

升级保持相同 Compose 项目名和卷映射，使用 `docker compose up -d` 更新容器，不执行 `down -v`、卷清理或插件目录覆盖。备份/迁移必须同时保留数据库与插件文件卷，仅备份 ZIP 文件不能恢复发布状态。

在纯主站版本之间回退镜像也不回退插件。不要直接回退到仍会自动安装内置插件的历史版本，否则旧启动逻辑可能修改未由管理员接管的旧插件。

## 插件兼容约定

服务器在部署健康检查通过后，只保留本站最近两个完整正式 tag 的镜像（backend、frontend、MCP 三者齐全）。清理脚本不删除数据卷、插件、上传内容或其他应用镜像，也保护仍被容器使用的版本。Git tag 和远端镜像仓库历史不在此清理范围内。

主站升级必须继续提供 `apiVersion: 1` 对应的 `__FYUO_PLUGIN_HOST_V1__`、共享 React/Router、既有 props、资源 URL、设计变量与业务 API。破坏性修改需引入新契约并保留旧契约，不能要求已上传插件跟随主站重新构建。

CI 使用历史包验证旧插件在新宿主中的加载与编辑行为，同时检查空站、自定义首页、上传发布、排序与重启持久性。CI 的插件构建/回归测试不等于部署：测试产物不会随主站发布。

“不影响插件”覆盖文件、版本、状态和现有契约；外部服务或插件自身缺陷仍需分别处理，不承诺任意未来破坏性框架升级自动兼容。
