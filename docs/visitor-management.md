# 文章访问管理

管理后台的访问记录仅统计文章打开事件，不统计首页或插件页浏览。`browser_count` 是筛选范围内不同浏览器标识的数量，不等于实际访客人数。同一浏览器清除存储或换设备会产生新标识。

## 查询接口

管理员 Bearer token 访问 `GET /api/v1/visit-records`。原有 `data` 数组保持兼容，新增：

- `total`：筛选后的记录总数，不受分页限制。
- `browser_count`、`article_count`：筛选范围内的不同浏览器标识数、文章数。
- `page`、`page_size`、`total_pages`：实际返回的页码、每页条数及总页数。没有记录时页码为 1，总页数为 0。

参数：`sort=latest|oldest`，`page`（默认 1），`page_size`（默认 50，最大 200），`article_id`，`search`（最多 120 字符，按文章标题、IP、浏览器标识作字面包含搜索），`from` 和 `until`（RFC3339，起点包含、终点不包含）。后台按浏览器所在时区将选择的结束日期转换为次日零点。无效参数返回 400；非管理员没有查询权限。

排序同时使用访问时间和记录 ID，保证同时间记录顺序稳定。统计与当前页在同一 PostgreSQL 只读快照中查询。新访问持续写入时，不同页请求仍可能发生位置变化；需要最新结果时使用“刷新记录”。

## 代理地址配置

后端默认不信任代理头。生产环境在后端 `.env` 中配置 `TRUSTED_PROXY_CIDRS` 为反向代理所在的受控 Docker 网络 CIDR（多个值以逗号分隔），然后重建后端容器。用 `docker network inspect` 确认实际网段，不能直接照抄其他环境，也不要配置 `0.0.0.0/0`。

仅可信网络的连接可使用 `X-Real-IP`。边缘 Nginx 以 `$remote_addr` 覆盖该头及 `X-Forwarded-For`，后端不读取外部传入的 XFF 链。后端端口保持仅 Docker 内部开放；该网络内的其他服务也属于受信任边界。新增 CDN 或其他代理层时需重新核对地址来源。

已存为代理 IP 的历史记录无法可靠还原，保留原值。城市查询失败显示“未识别”，私有地址显示“内网地址”。

## 本次变更边界

本次升级查询、展示和代理地址识别，不自动开启 Redis Streams 迁移、不删除历史数据、不修改插件。当前旧计数路径仍将浏览计数与访问明细分别写入，数据库写入失败时仍存在明细缺失风险。持久队列切换需按 `visitor-pipeline.md` 单独迁移并验证城市补全，不能仅打开开关。
